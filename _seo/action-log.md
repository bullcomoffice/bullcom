# 対策台帳（bullcom.jp）

週次・月次で決めた対策を A-番号 で採番して管理する。
効果検証が終わるまで消さない。ステータスは 🔵検証中 / ⏳継続観察 / ✅完了 / ❌棄却。

| ステータス | 意味 |
|---|---|
| 🔵検証中 | 実施済み。次の週次で効果を判定する |
| ⏳継続観察 | 効果が出るまで時間がかかる。複数週またぎで観察 |
| ✅完了 | 効果が確認できた、または恒久対応が済んだ |
| ❌棄却 | 効果なし・不要と判断した（理由を残す） |

---

## A-1 HTTPS強制がない（http が 200 を返す） 🔵検証中

- **検出**: 2026-08-30 初回外形チェック。`http://bullcom.jp/` が 301 せず **HTTP 200** を返す
- **なぜ問題か**: http/https が別URLとしてインデックスされうる。姉妹サイト bullcom.net で
  同じ状態を4ヶ月見逃した実績がある（あちらの A-17）
- **対策**: Cloudflare 側で「Always Use HTTPS」を有効にする
- **検証方法**: `npm run seo:check` の「http→https 301」が ✅ になること

## A-2 末尾スラッシュの正規化が 307（一時） 🔵検証中

- **検出**: 2026-08-30 初回外形チェック。`/blog/{id}/` → `/blog/{id}` が **HTTP 307**
- **なぜ問題か**: Googleは一時リダイレクトでは評価を統合しないため、同一記事が2URLで
  インデックスされうる。canonical はあるが、301 のほうが確実
- **対策**: Cloudflare の Static Assets 設定、または `public/_redirects` での恒久化を検討
- **検証方法**: `npm run seo:check` の「末尾スラッシュ 301正規化」が ✅ になること

## A-3 sitemap.xml の動的生成をデプロイ 🔵検証中

- **背景**: 手書きの sitemap が 2026-07-13 以降更新されず、本番は **21URL（記事11本）**のまま。
  公開57記事に対し46本が未掲載
- **対策**: `app/sitemap.ts` で microCMS から全件生成（コミット `1eec6d9`・**未push**）
- **残作業**: push → Search Console でサイトマップの取得を確認
- **検証方法**: 外形チェックの sitemap URL数が 67 前後になり、末尾スラッシュ混入が 0 件になること

## A-4 記事 meta description の自動生成をデプロイ 🔵検証中

- **背景**: 本番の記事 description が**タイトルと完全一致**。検索結果でスニペットが
  タイトルの繰り返しになっている
- **対策**: `lib/excerpt.ts` で本文から抜粋を生成（コミット `19a5809`・**未push**）
- **残作業**: push
- **検証方法**: 外形チェックの「ブログ description がタイトルと別文」が ✅ になること。
  その後、GSCで表示回数の多い記事のCTRが動くかを月次で確認する

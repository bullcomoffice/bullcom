効果検証が終わるまで消さない。ステータスは 🔵検証中 / ⏳継続観察 / ✅完了 / ❌棄却。

| ステータス | 意味 |

| ⏳継続観察 | 効果が出るまで時間がかかる。複数週またぎで観察 |

## A-1 HTTPS強制がない（http が 200 を返す） ✅完了

- **検出**: 2026-08-30 初回外形チェック。`http://bullcom.jp/` が 301 せず **HTTP 200** を返す
- **なぜ問題か**: http/https が別URLとしてインデックスされうる。姉妹サイト bullcom.net で
  同じ状態を4ヶ月見逃した実績がある（あちらの A-17）
- **対策**: ダッシュボード設定ではなく `src/worker.js` で対応（`run_worker_first = true` のため
  Worker が全リクエストを先に受ける）。https・非www・末尾スラッシュ無しの3条件をまとめて
  評価し、差分があるときだけ301を1回返す（コミット `3e2e362`）
- **結果**: 2026-08-30 デプロイ後の外形チェックで `HTTP 301 -> https://bullcom.jp/` を確認 ✅

## A-2 末尾スラッシュの正規化が 307（一時） ✅完了

- **検出**: 2026-08-30 初回外形チェック。`/blog/{id}/` → `/blog/{id}` が **HTTP 307**
- **なぜ問題か**: Googleは一時リダイレクトでは評価を統合しないため、同一記事が2URLで
  インデックスされうる。canonical はあるが、301 のほうが確実
- **対策**: A-1 と同じ Worker の正規化で対応（アセット層に渡る前に301を返す）
- **結果**: 2026-08-30 デプロイ後の外形チェックで `HTTP 301 -> /blog/{id}` を確認 ✅

## A-3 sitemap.xml の動的生成をデプロイ ⏳継続観察

- **背景**: 手書きの sitemap が 2026-07-13 以降更新されず、本番は **21URL（記事11本）**のまま。
  公開57記事に対し46本が未掲載
- **対策**: `app/sitemap.ts` で microCMS から全件生成（コミット `1eec6d9`・**未push**）
- **結果**: 2026-08-30 デプロイ完了。外形チェックで **67 URL・末尾スラッシュ混入0件** を確認 ✅
- **継続観察**: Search Console でサイトマップが「成功しました」になり、検出URL数が67になるか。
  そのあとインデックス登録数が21相当から増えるか（次回以降の週次・月次で追う）

## A-4 記事 meta description の自動生成をデプロイ ⏳継続観察

- **背景**: 本番の記事 description が**タイトルと完全一致**。検索結果でスニペットが
  タイトルの繰り返しになっている
- **対策**: `lib/excerpt.ts` で本文から抜粋を生成（コミット `19a5809`・**未push**）
- **結果**: 2026-08-30 デプロイ完了。外形チェックで description が **116字の本文抜粋**（タイトルと別文）
  になったことを確認 ✅
- **継続観察**: 表示回数の多い記事のCTRが動くかを月次で確認する。
  もともと「順位9台・224表示でCTR 0%」だった記事群が対象

## 記録: 2026-08-30 初回対応

A-1〜A-4 を同日に処理し、外形チェックは **17/17 PASS** になった。

- A-1 / A-2 は Cloudflare のダッシュボード設定ではなく Worker のコードで解決した。
  `run_worker_first = true` で Worker が全リクエストを先に受けるため、アセット層が
  307 を返す前に 301 で正規化できる。設定がリポジトリ上に残るので、
  ダッシュボードの設定が誰かに戻される事故も防げる。
- A-3 / A-4 は実装済み・未デプロイだった。`deploy.yml` は push では起動せず
  `repository_dispatch` / `workflow_dispatch` のみなので、`gh workflow run deploy.yml`
  で手動起動した。**push だけではデプロイされない**点は次回以降も注意。

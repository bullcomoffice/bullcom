# 月次レビュー（bullcom.jp）— GSC / GA4 / マップ / AI検索

**毎月最終日曜 9:00・1時間**。その週の週次レポートは実施せず、本レビューが兼ねる。
タイミングと手順の定義は [`report-operation.md`](./report-operation.md)。

対象期間は前回月報の翌日〜実施日前日（週次ログ4〜5週分）。
暦月の数字が要る項目は GSC の「過去28日」も併記する。

## 0. 週次分の引き継ぎ（月報が週報を兼ねるため必須）
1. 外形チェック（`npm run seo:log`）— [`health-log.md`](./health-log.md) の直近と比較し退行を指摘
2. **答え合わせ** — [`action-log.md`](./action-log.md) の 🔵検証中 / ⏳継続観察 のステータス更新
3. 当週データの取得と [`weekly-log.md`](./weekly-log.md) への記録

## 1. 月次レビュー本体
1. **週次データ4〜5週分の推移をグラフ化**（表示回数/クリック/CTR/平均順位 — weekly-log.md から集計）
2. **主軸キーワードの平均掲載順位推移**（最新の定義は [`README.md`](./README.md) の「対象キーワード」）
   > 個別KWの精査はここ（月次）が担当。週次では追わない。
   > あわせて毎月、**選定時に存在しなかった新規クエリの台頭**を確認し、必要なら主軸KWを入れ替える
3. **コンバージョン**: お問い合わせフォーム送信数（GA4）
4. **GEO引用率の変化**: 週次のGEO引用テスト○×の月間集計
5. **リライト候補選定**: GSCで表示回数多×順位低の記事
6. **翌月の記事テーマ 3〜5本決定**

## 2. GSC の健全性確認
プロパティ: `sc-domain:bullcom.jp`

1. **検索パフォーマンス**（過去28日）— 合計クリック/表示/CTR/平均順位。伸びた・落ちたクエリをメモ
2. **ページのインデックス登録** — 「登録済み」数の推移。「重複・正規未選択」が減っているか
3. **URL検査（トップ）** `https://bullcom.jp` が登録されているか
4. **サイトマップ** — `https://bullcom.jp/sitemap.xml` が「成功しました」か / 検出URL数
5. **拡張（構造化データ）** — FAQ / パンくず / 記事 のレポートにエラーが出ていないか
6. **インデックス登録リクエスト**（必要時・ユーザー承認後）

## 3. リッチリザルトテスト（ログイン不要）
https://search.google.com/test/rich-results で確認
- トップ `https://bullcom.jp` → Organization / LocalBusiness
- `https://bullcom.jp/faq` → FAQPage
- `https://bullcom.jp/area/kobe` → FAQPage
- ブログ記事1本 → Article / BreadcrumbList

## 4. Googleマップ / ブランド検索
- 「BULLCOM 神戸」「パソコン修理 神戸市西区」等でナレッジパネル・マップに出るか
- GBP のクチコミ件数・平均評価（`node scripts/tools/check-gbp-reviews.cjs`）

## 5. GEO（AI検索での露出）
- ChatGPT / Claude / Perplexity で「神戸 パソコン修理 おすすめ」「明石 パソコン修理 持ち込み」等を質問し、
  bullcom.jp が引用/言及されるか。されれば引用箇所をメモ
- 姉妹サイト bullcom.net（セキュリティ領域）と競合しない、**.jp の担当領域を名指しした質問**も必ず入れる
  （「起動しない」「データ復旧」「出張修理」等）。競合する質問だけ見ていると .jp の実力が測れない

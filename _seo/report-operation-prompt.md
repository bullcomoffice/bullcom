# 他セッションへ運用を反映するためのプロンプト

週報・月報の運用（日曜週報＋最終日曜月報／**カレンダー登録のみ・自動起動なし**）を
他プロジェクトのセッションへ持ち込むための、そのまま貼り付けられるプロンプト。
ルールの本文は [`report-operation.md`](./report-operation.md)。

> **前提**: スケジュールタスクによる自動起動は置かない。Googleカレンダーに予定だけを入れ、
> それを見て実施したいときに Claude Code へ指示する運用。

---

## 1. 既存の運用をこのルールに合わせるとき

```
週報・月報の運用を変更します。以下に合わせてください。

## 新しい運用
- 週報: 毎週【日曜】（変更前は月曜など）
- 月報: 毎月【最終日曜】（変更前は毎月1日）
- 最終日曜は週報を実施せず、月報が週報を兼ねる
- **自動起動のスケジュールタスクは置かない。** Googleカレンダーに予定だけを登録し、
  それを見て実施したいときに指示する運用にする。既存のスケジュールタスクがあれば削除する。

## なぜ変えるか
- 日曜にすると対象期間が週の区切り（日〜土）と一致する。月曜実施では
  「先週月〜日」を見る形でGSCの週次バケットと1日ずれていた。
- 月報を最終日曜に固定すると、日曜1本で運用が閉じる。「毎月1日」は曜日が
  毎月動くため、週報と重なる週・空く週が生じていた。

## カレンダー登録の仕様
カレンダー: bullcom.office@gmail.com

- 週報: RRULE `FREQ=WEEKLY;BYDAY=SU`
- 月報: RRULE `FREQ=MONTHLY;BYDAY=-1SU`
- 予定名は「【〈サイト名〉】SEO/GEO 週次レポート（15分）」
  「【〈サイト名〉】SEO/GEO 月次レビュー（1時間・最終日曜）」の形式
- 予定は「予定なし（FREE）」扱いにして他の予定をブロックしない
- 説明文に必ず入れるもと:
  ・★ 最終日曜はスキップ（同日の月次レビューが週次を兼ねる）※月報側は「この日は週次を実施しない」
  ・【始め方】どのディレクトリのセッションで何と言えば始まるか
  ・進め方の手順、記録先のフルパス、対象キーワード、サイト固有の注意

## 実施時刻（日曜。重ならないように割り当てる）
- 09:00〜 bullcom.net ／ 11:00〜 bullcom.jp ／ 12:00〜 boatkaitori.com
- 新しいサイトはこれらと重ならない時間にする

## 守ること
- 既存の予定の中身（対象KW・記録先・GSCプロパティ・注意書き）は引き継ぐ。
  日時と「最終日曜の扱い」の追記だけを変更する。
- **同じサイトの旧い予定が残っていないか必ず確認する。** 旧運用（月曜／毎月1日）の
  繰り返し予定が残っていると二重になる。見つけたら消してよいかユーザーに確認する。
- 変更後、今後5〜6回の日曜がどう展開されるかを一覧で示して確認すること。
```

## 2. 週報・月報を新規に作るとき

```
このプロジェクトにSEO/GEOの週報・月報の運用を新設してください。
ルールは D:\Data\Projects\Next\bullcom\_seo\report-operation.md に従います
（実装済みの参考例が同ディレクトリの _seo/ 一式）。

## スケジュール
- 週報: 毎週日曜（最終日曜はスキップ）／15分
- 月報: 毎月最終日曜のみ／1時間。週報を兼ねる
- **自動起動はしない。** Googleカレンダー（bullcom.office@gmail.com）に予定だけ登録する。
  週報 RRULE `FREQ=WEEKLY;BYDAY=SU` ／ 月報 RRULE `FREQ=MONTHLY;BYDAY=-1SU`
- 実施時刻は他サイトと重ねない（09:00 bullcom.net / 11:00 bullcom.jp / 12:00 boatkaitori.com）

## 週報の中身（15分）
1. 外形ヘルスチェック — 退行があればそれを最優先の問題点にする
2. 答え合わせ — 対策台帳の「🔵検証中」「⏳継続観察」を今週データで検証しステータス更新
3. データ収集（過去7日 = 前週日〜土）
   GSC（表示/クリック/CTR/平均順位・主軸KW別）／GA4（セッション・直帰率・新規記事PV）／
   新記事の索引状況／GBP（表示・電話タップ・経路検索）／GEO引用テスト（ChatGPT・Claude・Perplexity ○×）
4. 問題点抽出 — 1〜3個に絞って言語化
5. 対策立案 — 承認されたものを対策台帳にA-番号で採番
6. 記録 — 週次ログに追記、git commit & push

週報でやらないこと（月報に回す）:
個別KWの順位精査／推移のグラフ化／リライト候補の選定／記事テーマ決定

## 月報の中身（1時間）
対象期間は前回月報の翌日〜実施日前日（週次ログ4〜5週分）。

0. 週次分の引き継ぎ（必須。省くとその週の答え合わせが抜け落ちる）
   外形チェック／答え合わせ／当週データの取得と週次ログへの記録
1. 週次データ4〜5週分の推移をグラフ化（表示/クリック/CTR/順位）
2. 主軸KWの平均掲載順位推移＋**選定時に無かった新規クエリの台頭**を確認しKWを見直す
3. コンバージョン（GA4のフォーム送信数）
4. GEO引用率の月間集計（週次○×の集計）
5. インデックス健全性（登録済み数・重複/正規未選択の減少・URL検査・サイトマップ・構造化データのエラー）
6. リライト候補選定（表示回数多×順位低）
7. 翌月の記事テーマ3〜5本決定
8. 記録 — 月次チェックリストの「記録」欄に追記、commit & push

## 作るもの
- _seo/README.md（サイト固有の前提・対象KW・実務メモ）
- _seo/weekly-log.md（テンプレ付き・最新を上に追記）
- _seo/monthly-review.md（チェックリスト兼記録先）
- _seo/action-log.md（対策台帳。🔵検証中 / ⏳継続観察 / ✅完了 / ❌棄却）
- _seo/health-log.md（外形チェック履歴。スクリプトが --append で追記）
- scripts/seo-healthcheck.mjs（依存なし・Node18+ の fetch のみ。npm run seo:check / seo:log）
- Googleカレンダーの繰り返し予定2件（上記の仕様で。説明文に始め方・手順・記録先・注意を書く）

## 外形チェックで見る項目
トップ200／www正規化 301／http→https 301／末尾スラッシュの301正規化／canonical／
sitemap.xml（URL数・末尾スラッシュ混入）／robots.txt（AIボット許可・Sitemap行）／llms.txt／
LocalBusiness／FAQPage／記事の構造化データ／記事descriptionがタイトルと別文であること

⚠️ サイトごとに**正規形が違う**。www と末尾スラッシュの有無は必ず対象サイトの実装を
確認してから判定を書くこと（bullcom.jp は非www・末尾スラッシュ無し、
bullcom.net は末尾スラッシュ有り、boatkaitori.com は www有り・末尾スラッシュ有り）。

⚠️ description の判定でtitleからサイト名を取り除くとき、**先頭の区切り文字で分割しない**こと。
記事タイトル自体に区切り文字が含まれると前半だけを拾い、同一なのにPASSする。
サイト名サフィックスを末尾から除去して比較する。

⚠️ デプロイの起動条件はサイトごとに違う。push で走るとは限らない
（bullcom.jp は workflow_dispatch のみで、gh workflow run deploy.yml が必要）。

## 最後に
作成後、外形チェックを1回実行して現状を把握し、失敗項目があれば対策台帳に
A-番号で起票してから報告してください。
```

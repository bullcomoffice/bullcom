# レポート運用ルール（週報・月報）

2026-08-30 改定。**このファイルが週報・月報の運用の正**。
各プロジェクトのスケジュールタスクは、ここで決めた内容に合わせて各セッションで反映する。

## 変更点（2026-08-30）

| | 変更前 | 変更後 |
|---|---|---|
| 週報 | 毎週**月曜** 9:00 | 毎週**日曜** 9:00 |
| 月報 | 毎月**1日** 9:00 | 毎月**最終日曜** 9:00 |
| 最終日曜の週報 | （月曜週報なので概念なし） | **実施しない**（月報が代替する） |

### なぜ日曜にするか
週の区切り（日〜土）と対象期間が一致する。月曜実施では「先週月〜日」を見る形で、
GSCの週次バケットと1日ずれていた。日曜朝に前日土曜までの確定データを見れば、
対象期間＝直近7日がそのまま前週（日〜土）になる。

### なぜ最終日曜に月報を寄せるか
「毎月1日」は曜日が毎月動くため、週報と重なる週・空く週が生じていた。
最終日曜に固定すると、月に4〜5回ある日曜のうち1回が月報、残りが週報、と
**日曜1本で運用が閉じる**。

## 最終日曜の判定

「今日から7日後が翌月なら、今日が当月最後の日曜」。

```bash
# Git Bash
if [ "$(date -d '+7 days' +%m)" != "$(date +%m)" ]; then echo "last-sunday"; else echo "normal-sunday"; fi
```

```powershell
# PowerShell
if ((Get-Date).AddDays(7).Month -ne (Get-Date).Month) { "last-sunday" } else { "normal-sunday" }
```

cron は「第N曜日」を表現できないため、**週報・月報とも `0 9 * * 0`（毎週日曜）で起動し、
プロンプト冒頭でこの判定を行って自分の担当日かを決める**。
（`0 9 22-28 * 0` のような書き方は、cron実装によって曜日と日付がAND/ORのどちらで
評価されるかが変わるため使わない。）

- 週報タスク: 最終日曜なら「本日は月次レビュー日です」と一行だけ返して終了
- 月報タスク: 最終日曜でなければ一行だけ返して終了

## 週報（毎週日曜 9:00 / 15分）

**対象期間**: 前週日曜〜土曜の7日間（実施日前日までの確定データ）
**目的**: 答え合わせ → 問題点抽出 → 対策 → 翌週に効果検証（PDCAビルドアップ）

### 手順
1. **外形ヘルスチェック** — 自動チェックスクリプトを実行。退行（❌）があれば、それを最優先の問題点にする。
2. **答え合わせ** — 対策台帳（`_seo/action-log.md`）の「🔵検証中」「⏳継続観察」を列挙し、
   今週のデータで効果が出たかを確認 → ステータス更新（✅ / ⏳ / ❌）。
3. **データ収集**（過去7日）
   - GSC: 表示回数 / クリック / CTR / 平均掲載順位（サイト全体）＋主軸キーワード別
   - GA4: セッション / 直帰率 / 新規記事PV
   - 新記事の索引状況（URL検査で「登録済み」か）
   - GBP: 表示回数 / 電話タップ / 経路検索
   - GEO引用テスト: ChatGPT / Claude / Perplexity で指定質問をし、自社が出るか（○×）
4. **問題点抽出** — 前週比の悪化・表示多×順位低のクエリ・未インデックス記事・GEO引用ゼロ等から、
   **1〜3個に絞って**言語化する。
5. **対策立案** — 各問題点に対策を提案し、承認されたものを `_seo/action-log.md` に A-番号で採番。
   すぐ実装できるもの（コード・記事修正）は承認を得てその場で実施。
6. **記録** — `_seo/weekly-log.md` に当週エントリを追記（前週対策の効果 → データ → 問題点 → 今週の対策）。
   git commit & push。

### 週報でやらないこと（月報に回す）
- 個別キーワードの順位精査（週次のブレが大きく、週単位では判断できない）
- 推移のグラフ化
- リライト候補の選定
- 翌月の記事テーマ決定

### 注意
- 15分想定。データが取れない項目はスキップし「-」で記録してよい。
- フォーム送信・インデックス登録リクエスト・デプロイはユーザーの明示承認後に行う。
- ユーザーが忙しいときは、外形サマリー＋検証待ちの対策一覧だけ提示して終了してよい。

## 月報（毎月最終日曜 9:00 / 1時間）

**対象期間**: 前回月報の翌日〜実施日前日（＝週次ログ4〜5週分）
**重要**: 月報はその週の週報を**兼ねる**。週報の必須項目（外形チェック・答え合わせ・当週データ・記録）を
月報の中に含めること。含めないとその週の答え合わせが抜け落ちる。

> 月末の数日（最終日曜の翌日〜月末）は翌月の月報に含まれる。
> 暦月とは数日ずれるが、週次ログを積み上げる方式なので集計に穴も重複も出ない。
> 暦月の数字が必要な項目（GSCの過去28日サマリー等）は、別途その値も併記する。

### 手順
1. **外形ヘルスチェック** — 実行し、`_seo/health-log.md` の直近履歴と比較。退行があれば指摘。
2. **答え合わせ**（週報から継承） — `_seo/action-log.md` の検証中・継続観察のステータス更新。
3. **総括** — `_seo/weekly-log.md` の4〜5週分を集計し、表示回数 / クリック / CTR / 平均順位の推移をグラフ化。
4. **主軸キーワードの順位推移** — 平均掲載順位の月次推移。
   あわせて**選定時に存在しなかった新規クエリの台頭**を確認し、必要なら主軸KWを入れ替える。
5. **コンバージョン** — GA4 でお問い合わせフォーム送信数。
6. **GEO引用率の変化** — 週次のGEO引用テスト（○×）を月間集計。
7. **インデックス健全性** — 登録済みページ数の増減、「重複・正規未選択」の減少、
   トップページのURL検査、サイトマップの取得状況、構造化データ（FAQ / パンくず / Article）のエラー有無。
   必要ならリッチリザルトテストで確認。
8. **リライト候補の選定** — GSCで表示回数多×順位低の記事を洗い出す。
9. **翌月の記事テーマを3〜5本決定**。
10. **記録** — 月次チェックリストの「記録」欄に追記（当月の数値・リライト候補・翌月テーマ）。commit & push。

### 注意
- GSC / GA4 はユーザーのログインと対話が必要。ブラウザ操作・フォーム送信・
  インデックス登録リクエスト等はユーザーの明示承認を得てから。
- Chrome MCP は「Home」ブラウザを選択する。
- ユーザーが今は不要と言えば、外形サマリーだけで終了してよい。

## 適用対象のスケジュールタスク

bullcom.jp の2件は本ルールで**新設済み**。bullcom.net と huneya は**まだ変更していない**ので、各セッションで以下に合わせて反映する。

| タスクID | 対象 | 現行 cron | 変更後 cron | ガード |
|---|---|---|---|---|
| `bullcom-seo-weekly-review` | bullcom.net | `0 9 * * 1`（月9:00） | `0 9 * * 0`（日9:00） | 最終日曜なら実施しない |
| `bullcom-seo-monthly-review` | bullcom.net | `0 9 1 * *`（1日9:00） | `0 9 * * 0`（日9:00） | 最終日曜のみ実行 |
| `huneya-search-terms-review` | huneya.jp 広告 | `23 10 1 * *`（1日10:23） | `23 10 * * 0`（日10:23） | 最終日曜のみ実行 |
| `huneya-measurement-health` | huneya.jp 計測 | `17 9 * * *`（毎日） | **変更なし** | — |
| `bullcom-jp-seo-weekly-review` | bullcom.jp | （新設） | `0 11 * * 0`（日11:00） | 最終日曜なら実施しない |
| `bullcom-jp-seo-monthly-review` | bullcom.jp | （新設） | `0 11 * * 0`（日11:00） | 最終日曜のみ実行 |

- huneya の検索語句レビューは GAQL が `LAST_30_DAYS` 固定なので、実施日を月初から
  最終日曜に移しても集計期間の意味は変わらない。
- bullcom.jp は 2026-08-30 に新設した。実施時刻を**日曜11:00**にしたのは、
  bullcom.net（日9:00・月報は1時間）と huneya（日10:23）に重ならないようにするため。
  主軸キーワードは暫定値を置いてあるので、初回の週次で実データを見て確定する
  （→ [`README.md`](./README.md) の「対象キーワード」）。

### プロンプトに入れるガード文（貼り付け用）

週報タスクの冒頭:
```
まず今日が当月最後の日曜かを判定する。
  if [ "$(date -d '+7 days' +%m)" != "$(date +%m)" ]; then echo last-sunday; else echo normal-sunday; fi
last-sunday なら「本日は月次レビュー日のため週次レポートはスキップします」と一行だけ返して終了する。
normal-sunday のときだけ以下を実行する。
```

月報タスクの冒頭:
```
まず今日が当月最後の日曜かを判定する。
  if [ "$(date -d '+7 days' +%m)" != "$(date +%m)" ]; then echo last-sunday; else echo normal-sunday; fi
normal-sunday なら「本日は月次レビュー日ではありません」と一行だけ返して終了する。
last-sunday のときだけ以下を実行する。
なお本日は週次レポートを実施しないため、週次の必須項目（外形チェック・前週対策の答え合わせ・
当週データ・週次ログへの記録）も本レビューに含めること。
```

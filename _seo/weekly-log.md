### 7. 🔴 訂正：bullcom.org の「description が空」は誤検知だった

8/17の第4回で「bullcom.org はトップ以外16ページすべてで description タグが存在しない」と記録し、修正依頼まで出したが、**これは誤りだった**。ユーザーからの指摘を受けて再検証した結果、**全75URLに description が入っており、空は0件**。

**原因: 末尾スラッシュ無しのURLを叩いていた。**

```
curl https://bullcom.org/free      → 308（リダイレクト応答。本文にHTMLが無い）
curl https://bullcom.org/free/     → 200（description あり）
curl -L https://bullcom.org/free   → 200（description あり）
```

bullcom.org は `trailingSlash: true`。スラッシュ無しは308で正規URLへ飛ぶ。308の本文は空なので description が取れず、それを「タグが無い」と誤読した。**トップ（`/`）だけリダイレクトが起きないため、「トップだけ正常」という一見もっともらしいパターンに見えていた**のが、誤りに気づけなかった理由。

**サイトごとに設定が逆なので要注意:**

| サイト | trailingSlash | 正となるURL | 逆を叩くと |
|---|---|---|---|
| bullcom.org | **true** | `/free/` | `/free` → 308 |
| bullcom.jp | 未指定(false) | `/services` | `/services/` → 307 |

**再発防止（今後この種の点検では必ず守る）:**
1. **`curl -sL` を使う**（`-L` でリダイレクトを追う）。`-s` だけでは308の空応答を掴む
2. URLは**sitemap.xml から取る**（手打ちしない）。正規形が入っているため
3. **HTTPステータスも併記して確認する**。200以外が混じっていたら判定を疑う

**波及と対応:**
- bullcom.org セッションへ送った修正依頼を**撤回済み**（作業に着手していれば中断を依頼）
- truck-asahi.com / .co.jp へ渡した点検コマンドにも `-L` が無かったため、**両セッションに訂正を送付**。ただし両サイトはsitemapのURLがそのまま200で返るため、**「問題なし」という判定自体は正しかった**（`-L` 付きで15件ずつ再検証し OK 15 / 問題 0 を確認）
- **bullcom.jp の判定は影響なし**。固定ページ・ブログとも本番curlではなく**ローカルのビルド成果物 `out/*.html` を直接読んだ**ため。ブログの description がタイトル複製だったのはコード（`description: blog.title`）に起因する事実で、修正も妥当

**教訓**: 「一次情報を確認した」と言えるのは、確認の手段が正しいときだけ。curlの結果が想定と違うパターン（トップだけ正常）を見た時点で、手法を疑うべきだった。
